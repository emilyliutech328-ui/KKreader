> 目标：把现有「逐字竖排 + 写死字号 + 纯底色」的简易生成，升级成
> **横排自适应版式 + 边框纹理 + 主题图案 + 作者兜底**的封面系统
> 状态：仅设计，未动代码
> 涉及文件：`ui/widget/image/CoverImageView.kt`、新建 `model/cover/` 包

## 一、现状与差距

现有实现（`CoverImageView.generateCoverBitmap()`，约 70 行）：

```
逐字竖排 → 到底换列 → 字号硬编码 (w/7 → w/10)
描边(背景色) + 填充(强调色)
作者竖排在右下，字号 w/10
底色 = backgroundColor，字色 = accentColor
```

| 需求 | 现状 | 差距 |
|---|---|---|
| 横排 | 竖排逐字 | 需重写排版引擎 |
| 长书名自适应 | 硬编码三档字号，容易挤边 | 需按可用区试算字号 |
| 书内首句副标题 | 无 | 需新增内容提取 + 缓存 |
| 边框纹理 | 无 | 需新增绘制层 |
| 书名下方图案 | 无 | 需新增图案系统 |
| 作者兜底 | 空着就空着 | 需新增 20 个候选名池 |

## 二、版式设计

### 2.1 画布与安全区

封面比例维持 **3:4**（现有 `onMeasure` 已是 `width * 4/3`，不动）。

```
画布 300 × 400（示例）
┌───────────────────────────────────┐
│  ┌─ 外框 (inset 6) ─────────────┐  │
│  │ ┌─ 内框 (inset 12) ────────┐ │  │  ← 双线边框 + 四角装饰
│  │ │                          │ │  │
│  │ │      书  名  横  排      │ │  │  ← 主标题区（最大 56%）
│  │ │      (自适应 1~3 行)     │ │  │
│  │ │                          │ │  │
│  │ │        ◇ 图 案 ◇        │ │  │  ← 图案区（固定 12%）
│  │ │                          │ │  │
│  │ │                          │ │  │  ← 弹性留白
│  │ │              作 者        │ │  │  ← 作者区（右下，10%）
│  │ └──────────────────────────┘ │  │
│  └──────────────────────────────┘  │
└───────────────────────────────────┘
```

> 注：原设计里的「副标题区」已按决策取消，此处为最终版式。

**内容区**：`inset = 12dp`（按比例 `w * 0.04`），左右各留 8% 的呼吸空间。

### 2.2 垂直分区（按比例分配，剩余给标题）

| 区块 | 高度占比 | 说明 |
|---|---|---|
| 上边距 | 12% | 呼吸空间 |
| **标题区** | 弹性（最大 **56%**） | 占剩余空间（原 46%，副标题取消后多出 10%） |
| 间隔 | 4% | |
| **图案区** | 12% | 固定，居中 |
| 间隔 | 3% | |
| 弹性留白 | 剩余 | |
| **作者区** | 10% | 右下对齐 |

> 副标题取消后，这 18% 直接还给标题区，
> 效果是**长书名能多排一行、字号能大一档**。

### 2.3 标题自适应算法

不按字数查表，而是**试算到放得下为止**：

```
可用宽 = 画布宽 - 2 * inset
可用高 = 标题区高
字号从 w*0.185 起，每次乘 0.92 递减，下限 w*0.072
对每个字号：
    按字宽切行（中文按字、英文按词），最多 3 行
    若 行数 × 行高 <= 可用高  →  采用
若最小字号仍放不下：
    压到 3 行 + 末行省略号（…）
```

字号档位换算（300px 宽画布，供参考）：

| 书名长度 | 字号 | 行数 |
|---|---|---|
| ≤ 6 字 | ~55px | 1 行 |
| 7~10 字 | ~44px | 1~2 行 |
| 11~16 字 | ~36px | 2 行 |
| 17~24 字 | ~30px | 2~3 行 |
| > 24 字 | ~24px | 3 行 + 省略 |

**行高** = 字号 × 1.28（中文字距紧，别用 1.1 会糊在一起）。

### 2.4 横排的两个细节

1. **中英混排**：中文按字切，连续英文/数字按词切（不拆 `Vol.3`）。
2. **标点避头**：行首不能出现 `，。、）」` 等，遇到就挤到上一行末尾
   （或用 `lineHeadUnsafe` 集合把字符退回）。

## 三、副标题（已取消，不实现）

> **✅ 已决策（用户 2026-10-26 确认）：不提取副标题。**
>
> 原设计里"从书内首句生成副标题"这一整块**作废**，原因与取舍记录如下，
> 便于日后若想恢复时有据可查：

### 3.1 为什么原设计要绕这么大弯

封面在书架列表里逐项渲染，**不能在渲染路径里读章节正文**（本地书要解压、在线书要联网），
否则列表直接卡死。原方案是靠"异步提取 + ACache 缓存 + 渲染时只查缓存"来绕开这个约束。

### 3.2 取消后带来的简化（实际是好事）

- 版式里**不再需要副标题区**（原 18% 高度整个移除），
  这 18% 直接还给标题区 → **书名能多排一行、字号能大一档**
- 不需要 `CoverSubtitle.kt`，不需要 `ACache` 读写，不需要清洗规则
- 不需要"打开详情页时触发提取"的钩子，少一条隐性依赖
- 缓存 key 不用带副标题，逻辑更干净

### 3.3 版式变化（替代原 2.2 的分区表）

```
上边距 12%
标题区 弹性（最大 56%，比原来多 10 个百分点）
间隔   4%
图案区 12%
间隔   3%
弹性留白
作者区 10%
```

即：**去掉副标题区，标题区上限从 46% 提到 56%**。

## 四、边框与纹理

### 4.1 三层结构

```
第 1 层 底色        ← backgroundColor（沿用）
第 2 层 纹理        ← 极淡的印刷纹理（下面详述）
第 3 层 边框        ← 双线 + 四角装饰
```

### 4.2 纹理方案（三选一，可配置）

| 方案 | 画法 | 开销 | 观感 |
|---|---|---|---|
| **细网格**（推荐默认） | 每 4dp 一条 1px 线，alpha 6 | 低 | 类似书纸 |
| **网点** | 按确定性哈希撒点，alpha 8 | 中 | 类似漫画网点 |
| **无** | 纯色 | 零 | 最干净 |

> 点必须是**确定性随机**（用书名哈希做种子），否则每次渲染纹理都会变，缓存也失效。

### 4.3 边框

- 外框：inset 5dp，线宽 1.2dp，alpha 60
- 内框：inset 11dp，线宽 0.6dp，alpha 35
- 四角装饰：每角画两个 L 形短线，长度 = 内框 inset × 1.6
- 颜色统一取 `accentColor`，按 alpha 层次递减（外重内轻）

## 五、书名下方图案

### 5.0 关于"从网络小说/书籍配图取图"（先说结论）

**不建议**直接抓网络小说封面或书内插图当图案素材，两条硬伤：

1. **版权风险**。小说封面、插图归各自权利人所有。轻风阅读是 GPL 开源分叉，
   打包分发带版权图片会把项目直接置于侵权风险，也与"无广告、尊重内容权利人"的定位冲突。
2. **技术上也不合适**。那些图是**彩色位图**（封面 3:4 大图、插图比例各异），
   而封面装饰需要的是**单色、细线、可着色、任意缩放不失真**的图案。彩色位图放上去：
   - 与主题色冲突（封面底色/字色跟随主题变，插图色固定）
   - 缩小时糊成一团
   - 体积暴涨（每张 100KB 起，几十张就好几 MB）

**正确替代**：用**已授权的单色矢量图标库**。这类库天生单色描边、SVG 矢量、可任意着色，
正好匹配封面装饰需求。下面三个来源均已核实授权。

### 5.1 图案来源（三选，均需确认授权）

| 来源 | 授权 | 规模 | 风格 | 署名要求 |
|---|---|---|---|---|
| **自绘矢量**（原方案） | 自有 | 8 种 | 抽象几何 | 无 |
| **game-icons.net** | **CC BY 3.0** | 4000+ 枚 | 游戏/奇幻/冒险 | **必须署名原作者** |
| **Lucide** | **ISC** | 1600+ 枚 | 通用线性图标 | 保留版权声明 |

> 已实测核验：
> - game-icons.net 官方 About 页明确「provided under the terms of the
>   Creative Commons 3.0 BY license」，署名格式要求为
>   `Icons made by {author}. Available on https://game-icons.net`；
>   单图标页（如 `book-cover`）逐个标注作者与 CC BY 3.0。
> - Lucide 官方 License 页写明 ISC License。

**推荐组合**：以**自绘 8 种为基底**（零依赖、零体积、无授权负担），
再从 game-icons.net 挑 **20~30 枚**阅读题材图标作扩展集。

### 5.2 选型逻辑

**图案由书名哈希决定**，同一本书永远同一图案：

```
seed  = hash(name)
motif = MOTIFS[abs(seed) % MOTIFS.size]
```

> 「按内容选图案」已随副标题功能一并取消，只剩「按书名 / 关闭」两档。

| 3 | 星月 | 五角星 + 月牙 | 幻想 |

### 5.4 图案集合 B：game-icons.net 扩展集（建议 24 枚）

按阅读题材挑，该站全部为单色 SVG，天然适配：

|---|---|
| 书籍/阅读 | `book-cover`、`book-aura`、`book-storm`、`open-book`、`books-stack` |

> 并**逐枚确认作者**，因为 CC BY 要求署名到作者粒度。

### 5.5 矢量图标接入方式

**不能直接把 SVG 丢进 APK**（Android 原生不支持 SVG）。两条路：

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A. 转 VectorDrawable**（推荐） | 用 Vector Asset Studio / `svg2vector` 批量转成 `res/drawable/*.xml`，运行时 `VectorDrawableCompat` 加载并 tint | 纯原生、可 tint、每个仅 1~3KB、无损缩放 | 需预处理一次 |
| B. 运行时解析 SVG | 用项目已有的 `androidsvg` 加载 `.svg` | 免转换 | 体积略大、多一层解析 |

推荐 **A**：封面是高频渲染路径（列表逐项绘制），VectorDrawable 更快。
tint 用 `setTintList` 着色为 `accentColor`，与自绘图案视觉统一。

### 5.6 署名与合规（**必做**）

若采用 game-icons.net，必须：

1. 在「关于 → 开源许可」加入：
   ```
   Cover motif icons: Icons made by [作者列表]. Available on https://game-icons.net
   Licensed under CC BY 3.0.
   ```
2. 逐图标记录作者（CC BY 要求署名到**具体作者**，不是笼统写网站）。
   建议在 `assets/cover_motifs/LICENSE.md` 维护「图标名 → 作者」表。
3. 若采用 Lucide，保留 ISC 声明即可。

> 这步不做完等于侵权。**建议在实施第 4 步之前先把署名文件建好。**

### 5.7 统一规范（两套集合共用）

- 居中于「图案区」，最大边 = 画布宽 × 0.16
- 单色，颜色取 `accentColor`，alpha 55
- 自绘图案线宽 0.9dp；矢量图标按原始描边等比缩放
- 图案宽度超出「标题区最宽行」时自动缩到 0.85 倍
- **小尺寸封面（宽 < 120px）不画图案**（书架列表项看不清，白烧性能）

### 5.8 图案与标题的间距

图案顶端距最后一行标题底部 = `字号 × 0.6`（跟随标题字号缩放，避免大标题小图案的割裂感）。


### 6.2 分配规则（**必须确定性**）

```
若无作者：
    index = abs(hash(书名)) % 20
    fallbackAuthor = POOL[index]
```

> **为什么不真随机**：封面会被反复渲染（滚动、重绘、换主题），
> 真随机会导致"同一本书每次看到作者都不一样"，而且缓存失效。
> 用书名哈希保证**同一本书恒定分配同一个名字**，跨设备也一致。

### 6.3 使用边界

- 只用于**封面显示**，**不写入数据库、不写入书籍详情**
- 封面右下角以小字显示，不做特殊标注（用户明确要求"随机给设置一个"）
- 设置里留一个开关「无作者时用占位名」，默认**开**；关掉则作者区留空

> **✅ 已决策（用户 2026-10-26 确认）**：**不加任何提示说明**。
> 封面右下角直接显示占位名，不加"装饰性生成"之类的小字，也不在配置页加解释。
> 即原 6.3 里"建议加一行说明"的提议**作废**。

- ⚠️ 风险提示：这可能让用户误以为是真实作者。建议在关于页或封面配置页加一行小字说明「占位作者名为装饰性生成，非真实作者」。

## 九、性能与缓存（重点）

### 9.1 现有缓存有风险

```kotlin
private val nameBitmapCache by lazy { LruCache<String, Bitmap>(33) }
```

- 单张 300×400 ARGB = **480 KB**
- 33 张 ≈ **15.8 MB** —— 已经不小
- 新版封面绘制更复杂（纹理 + 图案），若再加宽高，容易 OOM

**对策**：
1. 缓存上限**按内存字节数**而非条目数：`LruCache<String, Bitmap>` 用 `sizeOf` 返回 `byteCount`，上限取 `maxMemory/8`
2. 列表里小尺寸（宽 < 120px）**不画纹理和图案**，只画标题+边框（可视面积太小，细节看不出，白烧性能）
3. 纹理按 4dp 网格画，避免逐像素

### 9.2 渲染优先级

```
宽 < 120px  →  简版（标题 + 细边框）        ← 书架列表
宽 >= 120px →  完整版（含纹理/图案/副标题）  ← 详情页/大网格
```

## 十一、明确不做

1. **不做**从封面取色（虽然已有 `Monet`，但封面取色会让同类书颜色相同，反而更单调）
2. **不做**真实随机作者（会变，见 6.2）
3. **不做**副标题提取（**用户已明确：不提取**，见第三节）
4. **不做**在列表渲染路径里联网（会卡）
5. **不做**在渲染路径里下载图案图片（图案必须内置，不联网）
6. **不做**占位作者的任何提示/免责说明（**用户已明确：不加**，见 6.3）
7. **不做**直接抓网络小说封面/书内插图当图案素材（**版权风险 + 彩色位图不适配**，见 5.0）
8. **不做**把 SVG 原始文件直接打进 APK（Android 不支持，须转 VectorDrawable）

## 十二、三项决策（已确认，2026-10-26）

| # | 待确认项 | 决策 | 对设计的影响 |
|---|---|---|---|
| 1 | 占位作者是否加提示说明 | **否，不加** | 封面右下角直接显示占位名，不加任何"装饰性生成"小字；配置页也不加解释 |
| 2 | 副标题提取时机 | **不提取**（整块取消） | 删除 `CoverSubtitle.kt`、删除副标题区（18% 高度还给标题）、删除 `coverSubtitle` 配置项、实施步骤少一步 |
| 3 | 竖排旧版式是否保留 | **保留** | `coverLayout` 提供 横排 / 竖排 切换，旧绘制逻辑不删，移入竖排分支 |

### 决策后的最终形态

- **版式**：横排（默认）/ 竖排（旧样式，可选）
- **标题**：横排自适应，字号试算，上限 3 行 + 省略号
- **图案**：8 种矢量图案，按书名哈希确定性选型，书名正下方
- **边框**：双线 + 四角装饰 + 可选纹理（细网格 / 网点 / 无）
- **作者**：无作者时从 20 个候选名中按书名哈希确定性分配一个，**直接显示、无提示**
- **副标题**：无
- **配置项**：`coverLayout`、`coverTexture`、`coverMotif`、`coverFallbackAuthor`、`coverBorder`
