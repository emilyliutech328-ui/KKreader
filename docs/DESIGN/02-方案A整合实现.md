## 二、内置在线书库

### 2.1 为什么不是"直接抓站内列表"

实测结论（多次验证，全部在当前网络下复现）：

| 端点 | 访客可访问 | 说明 |
|---|---|---|
| `/book/{aid}.htm` | ✅ | 书籍详情 |
| `/novel/{aid/1000}/{aid}/index.htm` | ✅ | 目录 |
| `/novel/{aid/1000}/{aid}/{cid}.htm` | ✅ | 正文 |
| `/modules/article/reviews.php` | ✅ | 书评 |
| `/sitemap.xml` | ✅ | 全站 4328 本书的 aid 来源 |
| `/modules/article/articlelist.php` | ❌ | 302 → 登录页 |
| `/modules/article/search.php` | ❌ | 302 → 登录页 |
| `/modules/article/toplist.php` | ❌ | 302 → 登录页 |
| 官方 app API `app.wenku8.com/android.php` | ❌ | 只返回 `<h1>Welcome</h1>`，已停用 |

**两个致命坑**：
1. **不能带 `charset` 参数**。`?charset=gbk` 会直接触发 Cloudflare 拦截（403 "Just a moment"）。
2. **UA 必须是 `Dalvik/2.1.0 (Linux; U; Android 11)`**。用 `Mozilla/5.0` 或完整 Chrome UA 都会被 CF 挡住。

所以"书库"由 App 自己维护一份书目索引：

```
sitemap.xml (4328 aid)
   ↓  逐本抓 /book/{aid}.htm（串行 + 重试，避开 CF 限流）
catalog.tsv：aid → 书名/作者/文库/状态/更新/字数/标签/简介/封面
   ↓  打包进 assets
书城界面：浏览、搜索、排序、分页 → 点进详情 → 走书源规则读目录正文
```

当前索引规模：**3147 本**（4328 本中抓取成功，其余为 CF 限流未取到），文件约 1.8 MB。

### 2.2 书源规则（`assets/defaultData/wenku8Sources.json`）

关键点：
- `header` 用 `@js:` 输出 Dalvik UA + Referer；
- 全部使用 **jsoup 标准 CSS**（不支持 `:eq()`/`:first`，那些是 jQuery 扩展，用了会 `SelectorParseException`）；
- `ruleBookInfo.tocUrl` 用 JS 由 `baseUrl` 推导 `/novel/{aid/1000}/{aid}/index.htm`；
- `ruleContent.content` 用 `@css:#content@html` 取整段正文。

已验证命中的选择器（真实页面）：

| 字段 | 选择器 |
|---|---|
| 书名 | `#content table:nth-of-type(1) tr:nth-child(1) b` |
| 作者 | `#content table:nth-of-type(1) tr:nth-child(2) td:nth-child(2)` |
| 更新 | `… td:nth-child(4)` |
| 字数 | `… td:nth-child(5)` |
| 封面 | `#content table:nth-of-type(2) tr td:nth-child(1) img@src` |
| 标签 | `#content … span.hottext:nth-of-type(1) b` |
| 最近章节 | `… span.hottext:nth-of-type(4) a` |
| 简介 | `… span.hottext:nth-of-type(5)` |

目录页的特殊结构：`table.css` 里每个 `<tr>` 并排 4 个 `<td class="ccss"><a>`，而卷标题是 `<td class="vcss">`（没有 `<a>`）。所以章节要按 `td.ccss a` 提取，不能按 `tr` 取。

### 2.3 书城界面

`StoreActivity`：搜索框（书名/作者/标签/文库）、三种排序（默认/更新/字数）、滚动分页、长按菜单（加入书架 / 书籍详情）。加入书架走标准书源链路，之后更新、下载、换源全都可用。

### 2.4 分类与排行（补站点关掉的部分）

站点把「分类导航」和「排行榜」也对访客关了，改用书目里已有的字段还原：

**分类**
- 按文库：14 个文库（其他文库 812、电击 449、角川 363、MF文库J 249、富士见 238、集英社 190、讲谈社 172、Fami通 152、GA 145、HJ 124、小学馆 121、少女文库 73…）
- 按标签：49 个标签（恋爱 1163、校园 1158、奇幻 1114、青春 999、后宫 902、欢乐向 784、战斗 777、冒险 639、悬疑 555、科幻 412…）
- 每项后面带书目数量，点进去就是对应书单。

**排行**（四张榜）
| 榜单 | 排序依据 |
|---|---|
| 热度榜 | 详情页的「作品热度」等级 S>A>B>C>D>E，同级按字数 |
| 最新更新 | 最后更新日期 |
| 最长篇幅 | 全文字数 |
| 已完结 | 完结优先，再按更新时间 |

热度等级是我专门加抓的一列（3147 本里 3065 本有等级：S 72、A 124、B 276、C 645、D 737、E 1211），这样"热度榜"才是真的按热度而不是瞎猜。

菜单里还有「全部书目」随时退回全量列表。搜索会在当前书单内过滤。

## 三、Edge 在线音色听书

### 3.1 协议实现

`EdgeProtocol.kt` 实现 `Sec-MS-GEC` 时间证明（300 秒窗口）。**这个算法已经用独立参考实现交叉验证**：

我用 Python 按 rany2/edge-tts 与 Wenku8 Flutter 的实现转写了同一算法，生成 5 组基准值，Kotlin 实现与之**逐字符一致**（`EdgeProtocolTest`，3 项全过）。这点最关键——算法错一个位就会 403。

`EdgeTts.kt` 负责 WebSocket 合成：
- 端点 `wss://speech.platform.bing.com/consumer/speech/synthesize/readaloud/edge/v1`
- 查询参数 `TrustedClientToken` / `ConnectionId` / `Sec-MS-GEC` / `Sec-MS-GEC-Version=2-143.0.3650.75`
- 请求头需 `Origin: chrome-extension://jdiccldimpdaibmpdkjnbmckianbfold`、Edge 143 UA、`Cookie: muid=<32hex>`
- 先发 `speech.config`（JSON），再发 SSML（`Path:ssml`）
- 二进制帧：前 2 字节为大端头部长度，头部含 `Path:audio`，之后是 MP3 数据
- 文本帧 `Path:turn.end` 表示结束
- 输出格式 `audio-24khz-48kbitrate-mono-mp3`；单段上限 3500 字节

### 3.2 与现有朗读体系的衔接

没有另起一套播放器，而是把 Edge 作为**一种特殊的在线朗读引擎**：

```
朗读设置 → 在线音色（EdgeVoiceDialog 选音色）
              ↓
EdgeTtsEngine.synthesize(text, rate) → MP3 流
              ↓
HttpReadAloudService（原样复用）
   ├─ ExoPlayer 播放
   ├─ SimpleCache 预缓存（preDownloadAudios 已实现"下一章前 10 段"预合成）
   ├─ MediaSession 锁屏/耳机线控/通知栏控制
   └─ 睡眠定时、段落跟随、0.5~3 倍速
```

这样预缓存和锁屏控制是**直接继承**的，不需要重写。

### 3.3 配置项

朗读设置页新增：

- **在线音色**：分组选择（普通话 / 粤语 / 台湾国语 / 其他），在线拉取音色列表，失败回落到内置 22 个常用音色。
- **失败时回落到系统朗读**：连续 3 次合成失败时提示可切换。
- **启用 Edge 在线音色**：总开关。
- **自定义 SSML**：留空用默认模板；可填自定义 `<speak>`，支持"恢复默认"。

## 四、玻璃拟态 / 莫奈 / 动态图标 / 多语言

### 4.1 玻璃拟态（`GlassUi`）

Android 上没有"模糊背后内容"的廉价方案，所以做分档：

- **Android 12+ 且非低端机**：`RenderEffect.createBlurEffect` 真模糊（高端 18px，中端 10px）。
- **其余设备**：半透明 + 顶部高光的渐变近似（视觉上仍是玻璃，零额外开销）。
- **墨水屏模式**：不启用。

已接入阅读菜单的顶部 TitleBar 与底部面板。

### 4.2 莫奈取色（`Monet`）

不引 `androidx.palette`，自己做：

1. 图片降采样到 96×96；
2. 按 4 bit/通道量化成 4096 个桶；
3. 过滤掉过暗/过亮/低饱和像素；
4. 打分 = 像素数 × 饱和度权重 × 明度居中性，取最高分桶的平均色作为种子；
5. 按主题明暗做 HSL 校正，生成 主色 / 深色 / 强调色（色相偏移 +24°）/ 背景色。

入口：主题设置 → **莫奈动态取色**（开关）+ **立即重新取色**（壁纸变了手动刷一次）。

### 4.3 动态图标与多语言

- 动态图标：基座已有 `launcherIcon` 偏好与多套 `ic_launcher*.xml`，未改动。
- 多语言：基座已有 `values / values-zh / values-zh-rHK / values-zh-rTW / ja / es / pt / vi`，本次所有新增文案**四份都补齐**（简中/繁中/港繁/台繁）。

## 五、立体书架性能开关

`PerfHelper` 分三档：

| 档位 | 判定 | 立体书架 | 玻璃模糊 |
|---|---|---|---|
| 低 | `isLowRamDevice` 或 < 3GB 或 ≤ 4 核 | **默认不显示** | 关闭 |
| 中 | 3~6 GB | 显示，动效收敛（`setReduceMotion`） | 开，10px |
| 高 | ≥ 6 GB | 显示，全动效 | 开，18px |

书架配置对话框新增 **"按设备性能自动简化 · 当前档位"** 开关，用户可关掉自动降级强行全开。

## 七、没做的事（需要你确认是否要补）

1. **书库增量刷新**：索引是构建期抓的（3147 本 / 站点共 4328 本），App 内还没有"联网补新书"入口。需要的话可以加手动刷新（复用同一套抓取逻辑）。
2. **书评/账号/云书架**：Wenku8 的社区功能没做（需要登录态，站点对访客限制多）。
3. **竖排/对页**：本次没做，属于方案 A 的 P4（原生重写成本高）。
4. **玻璃拟态覆盖范围**：目前只做了阅读菜单，书架/发现页/对话框还是原样式。全面铺开会动到大量布局，建议先看观感再决定。
5. **未抓到的那 1181 本**：主要是 CF 限流（并发过高会被临时挡）与个别页面结构差异。索引已覆盖热门书（S/A/B 级基本齐全），补全可再审一次。
